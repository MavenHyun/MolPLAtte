# Corpora

Generated by `scripts/write_corpora_manifest.py` from what is on disk. Do not hand-edit -- regenerate it.

## Naming

Two orthogonal axes, which earlier versions conflated:

- **content** -- which sources and which filter (`coconut-flavordb-filtered`)
- **build tag** -- the settings that determine whether two corpora are COMPARABLE (`r333-m2-h4-flavor24`): decomposition ratio, `min_rgroup_atoms`, `HASH_VERSION`, condvec mode and width

Two corpora may be compared only if their build tags match. The old `v3..v7` names were sequential fixes, not content variants, and could not express that distinction.

A `HASH_VERSION` mismatch is enforced at load time: the stored `rgroup_hashes`, the library keys and the loss's multi-positive grouping must all agree, and a mismatch would degrade retrieval silently rather than fail.

## What each is for

### `coconut-flavordb-filtered` — active

Both sources, COCONUT restricted to the odorant physicochemical envelope (MW 108-290, logP 0.4-4.5, TPSA<=53) derived from FlavorDB's own non-imputed labels, plus every known-flavor compound. 10.6% known-flavor density against a 0.62% base rate -- 17x enriched. Intended for pocket finetuning and flavor conditioning.

### `coconut-flavordb-full` — active

Both sources, unfiltered. The default pretraining corpus.

### `coconut-flavordb_v7` — superseded

Same content as coconut-flavordb-full. Retained because the three-arm condvec shuffle test was run against it; deleting it orphans those results.

### `coconut-only` — active

COCONUT alone. Natural-product chemistry with almost no flavor labels. The contrast arm for anything claiming a flavor effect.

### `flavordb-only` — active

FlavorDB alone. Every molecule carries a measured flavor label, so the condvec is dense. Small; use for conditioning experiments where label coverage matters more than scale.

## Shared build settings

All corpora above were built with the same decomposition, which is why their build tags agree:

```
method            naveja_recap  (RECAP bonds -> fragment tree -> connected
                                 subtrees as cores)
core ratio        1/3           dominates 0.4 on every axis at equal cost
max_cores         4
min_rgroup_atoms  2             removes single-atom R-groups; effective
                                vocabulary 46 -> 889
HASH_VERSION      4             total_num_hs, is_in_ring; hybridization
                                dropped (parent-context leakage)
condvec           flavor(24)    molecule-level, from measurement /
                                literature / physics -- never from structure
```

## Condition vector

24 bits: 5 taste primaries, 17 odor classes, `odorless`, `unknown`. Sources, in priority order, all exogenous to the molecular graph:

1. **measured** — FlavorDB by InChIKey (11,262 keys)
2. **mined** — LLM annotations at the `documented` tier ONLY, i.e. literature recall with a named source; 96.4% cite Good Scents, BitterDB or FEMA (1,927 compounds). `structural` and `close_analog` tiers are excluded because both are inferred from the graph.
3. **physics** — `odorless` where MW>350 and no sugar; a claim about volatility, not about missing data.

An all-zero vector is never emitted. Zero would mean "no flavor", and silently labelling 94% of the corpus flavourless would teach source provenance rather than flavour -- the same failure as the original 97-bit fragment condvec, which was computed from the intact molecule and so contained the R-group being predicted.

Shuffle test on `coconut-flavordb_v7` (25 epochs, logQ on):

```
no condition          H@1 0.3050
PERMUTED condition    H@1 0.3098   +1.6%  <- capacity effect
real condition        H@1 0.3164   +3.7%
```
The real-minus-permuted gap is 2.1% (~0.007 absolute), against a seed-to-seed spread of +-0.015. So the condvec does NOT leak -- a leak would show a large gap -- but it is also not demonstrably helping. Settling that needs seed replicates on all three arms.
